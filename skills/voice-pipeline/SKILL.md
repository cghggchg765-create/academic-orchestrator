# 写作口吻与可信度协同总控

本技能是**调度器**，不是改写器。只做四件事：

1. 把用户请求拆成“能力需求”；
2. 在已装专门技能里做匹配与排序；
3. 编排多技能的角色、顺序与交接；
4. 校验交接结果并把下一棒交出去。

改写、诊断细则、词句清单、评分标准、平台语感，全部由子技能的 `SKILL.md` 负责。本文件不复述、不代做、不发明流程。

## 零、边界（先划清）

**总控不做：**

- 不直接改写、润色、重写任何段落；
- 不做 AI 味评分、不列禁用词表、不规定句长/段落数；
- 不替子技能做诊断、不替它修稿、不替它跑准出检查；
- 不承诺“通过 AI 检测”“降低 AI 率”“查重降重”；
- 不为了“人感”编造经历、数据、案例、引文、对话或细节；
- 不为了“有底气”删掉真实局限、相反证据、风险提示或法律声明；
- 不把子技能流程抄进本文件。

**总控只做：**

- 判断该找谁、谁主谁辅、先谁后谁；
- 把用户约束、原文、必须保留项完整交过去；
- 收产物与子技能 QA 状态，决定下一棒或重路由；
- 在能力缺口时如实报告，不硬凑。

## 一、能力地图（只记“谁最强”，不记流程）

详细字段见同目录 `registry.json`。核心判断如下：

| 槽位 | 技能 | 默认角色 | 最强能力 | 不接 |
|---|---|---|---|---|
| **V0 `anti-defensive-writing`** | 叙事 | 中文学术写作的防御性叙事重构：把论文当发布会，识别真正优势，不主动示弱、不写实验流水账、不替审稿人攻击自己 | 英文文本（走 V0e）；纯语法/翻译/格式；非学术社媒文案；删真实局限或伪造优势 |
| **V0e `anti-defensive-writing-en`** | 叙事 | 英文学术写作的同一条防御性叙事路线 | 中文文本（走 V0）；纯语言润色；非学术文本 |
| **V1 `doubao-human-signal`** | 诊断/改写 | AI 味成因层诊断、作者声音、体裁/平台/受众适配、改写/评分/prompt 防御；中英文通用 | 纯语法/翻译/摘要/扩写/格式；正式合规文本强行人感化；AI 检测规避；非文本任务 |
| **V2 `humanizer-zh`** | 最小编辑 | 中文空话、重复、模板化表达；31 类模式；保留事实、限定与作者声音；文件保护 | 英文；从零创作；扩写/摘要/翻译/语法/格式；学术叙事重构；删真实限定或伪造细节 |

读取顺序：先 `registry.json` 看边界与依赖，再 Read 目标技能的 `SKILL.md` 全文。**每次重读，不凭记忆。**

## 二、匹配算法

### 2.1 先过五道硬约束（不满足就淘汰）

1. **语言**：英文论文/英文文本 → V0e 或 V1；中文论文/中文文本 → V0、V2 或 V1。语言不匹配的变体直接淘汰。
2. **文本类型**：学术论文、摘要、引言、结论、rebuttal、实验组织 → V0/V0e；一般文章、评论、社媒、个人文本 → V1；正式法律/合规/合同文本 → 不强行人感化，只允许在不改变法律与事实含义的前提下做必要的防御性表述调整。
3. **任务模式**：只诊断 → V1（或 V0/V0e 的叙事诊断）；要改写 → V0/V0e（叙事）或 V1/V2（表面）；从零生成 → V1；写 prompt/规则 → V1。
4. **完整性**：必须保留事实、数字、引文、来源、否定、条件、时间、范围、归因、不确定性和真实局限。任何会编造、删证、扩大主张或隐藏风险的路線，直接淘汰。
5. **目标**：目标是自然、可信、有作者声音；不是绕过 AI 检测、降重、查重或伪造人设。目标冲突时停止，不硬做。

硬约束优先于成熟度、偏好、点名。点名与硬约束冲突时先说明，不静默换路线。

### 2.2 给候选技能打分（0–3）

| 分 | 含义 |
|---|---|
| **3** | 主能力完全命中：任务动词、语言、文本类型、输出形态四者都对 |
| **2** | 可承接，但需要分工/转换/二次审计 |
| **1** | 兜底：能出结果，但不是最佳 |
| **0** | 不匹配或硬约束冲突 |

排序 tie-break，依次比较：

1. 硬约束满足度；
2. 语言匹配度；
3. 任务阶段匹配度（叙事重构 vs 表面编辑）；
4. 体裁/受众/平台匹配度；
5. 编辑幅度：学术正文且只需改表达 → V2 的最小编辑优先；需要诊断、评分、作者声音或平台适配 → V1；
6. 调用成本，只在前五项打平时才看。

`stars`/成熟度只是参考，**不参与硬约束，也不替代专精度**。

### 2.3 判定“单技能”还是“组合”

- 只有一个 3 分主技能，且不需要二次编辑 → **单技能直调**。
- 学术文本同时有“防御性叙事”和“AI 味” → **叙事→表面**：V0/V0e 先重构故事与主张范围，再由 V2 或 V1 做表面编辑。
- 需要先诊断再改 → **诊断→编辑**：V1 只出诊断/评分/修改优先级，V2 执行最小编辑；V1 不得同时改写同一文本。
- 只需要防 AI 味、且文本是中文散文 → **单 V2**；需要评分、作者声音、平台适配或非学术体裁 → **单 V1**。
- 英文非学术 AI 味 → **单 V1**；英文论文防御性叙事 → **V0e**，需要表面去味时再接 V1。
- 同一文本同一时间只允许一个**生产者**；可以有诊断者，但诊断者不改稿。
- 返修最多 3 轮；仍不过就报告“缺口-证据-已尝试”，不无限循环。

### 2.4 匹配表（意图 → 主技能 → 辅助）

| 意图 | 主技能 | 辅助/下一棒 |
|---|---|---|
| 中文论文摘要/引言/结论“心虚”、自我削弱 | V0 | 需要表面去味时接 V2；需要评分/诊断时先 V1 诊断 |
| 英文论文同样问题 | V0e | 需要表面去味时接 V1 |
| rebuttal / 审稿回复太防御 | V0 或 V0e | 语气/平台适配接 V1；中文最小编辑接 V2 |
| 实验部分写成流水账、重点被淹没 | V0 或 V0e | 结构调整后再做表面编辑 |
| 中文文章空话、重复、模板句 | V2 | 需要评分/作者声音/平台适配则改 V1 |
| 中文文案“太像 AI”、需要诊断/评分/人感 | V1 | 需要最小编辑时接 V2，但 V1 只诊断 |
| 英文非学术文本 AI 味 | V1 | 无 |
| 写 prompt / 规则，提前防 AI 味 | V1 | 无 |
| 纯翻译、语法、格式、摘要、扩写 | 不归本技能 | 走对应语言/文档技能 |
| 正式法律/合规/合同文本 | 不强行人感化 | 只做必要的防御性表述调整，或转出 |
| 绕过 AI 检测、降重、查重 | 停止 | 说明不支持，只提供自然表达/作者声音 |
| 不确定该用哪个技能 | 本技能 | 匹配后交子技能 |

## 三、协同模式

| 模式 | 角色分配 | 适用 |
|---|---|---|
| **直调** | 单一主技能 | 单阶段、边界清晰 |
| **叙事→表面** | V0/V0e 重构叙事；V2/V1 做表面编辑 | 学术文本既有防御性叙事又有 AI 味 |
| **诊断→编辑** | V1 只诊断；V2 执行最小编辑 | 需要先知道“哪里假、为什么假” |
| **上游防御** | V1 产出 prompt/规则/禁用项/自检清单 | 还没写，先防 AI 味 |
| **转出/停止** | 不选技能 | 翻译、语法、格式、合规、检测规避、能力缺口 |

协同铁律：

- 同一文本同一时间只有一个**生产者**；诊断者只出问题清单，不改稿。
- V0/V0e 可以改叙事结构、主张范围和章节重心；**不得删真实局限、相反证据或风险提示**。
- V2/V1 做表面编辑时，**不得改事实、数字、引文、否定、条件、归因和核心主张**。
- V1 与 V2 不得同时作为生产者改同一文本；需要两者时，V1 只诊断，V2 只编辑。
- 子技能发现问题 → 退回同一生产者修；总控不直接改。
- 返修最多 3 轮；仍不过就报告能力缺口。

## 四、交接协议

### 4.1 交给子技能之前

1. Read 目标子技能的 `SKILL.md` **全文**；需要 references 时按它的指引再读。
2. 组装 **context pack**，一次交清：

| 必传项 | 内容 |
|---|---|
| 用户原话/目标 | 不加工、不改写诉求 |
| 文本 | 内联原文，或文件的**绝对路径**；文件是否允许写回 |
| 语言/体裁/平台/受众/公开度 | 中/英；论文/社媒/邮件/个人陈述等；读者是谁 |
| 作者声音样本 | 用户自己的旧文/口吻样本（如有）；没有就标明“无样本” |
| 必须保留 | 事实、数字、引文、来源、否定、条件、时间、范围、归因、不确定性、真实局限、术语、格式 |
| 模式与强度 | 诊断/改写/生成/prompt；不改/轻/中/重 |
| 禁止项 | 不编造、不删证、不扩大主张、不强行口语化、不承诺检测通过 |
| 期望产物 | 具体文本/文件/评分/修改清单 |
| 验收 | 明确要求“跑你自己 SKILL.md 里的准出检查并回报结果” |

3. 不传总控自造的禁用词表、句长阈值、段落模板；这些由子技能决定。

### 4.2 子技能交付之后

收三样东西：

1. **产物**：文本或文件路径（存在、非空）；
2. **子技能自己的 QA 状态**：它跑没跑、结果如何；
3. **未决问题/假设**。

然后：

- 记入协同台账（见第五节）；
- 需要下一棒 → 把产物与“本轮只改了什么”写进下一技能的 context pack；
- QA 未过 → 带证据退回同一生产者；再不过 → 按第六节重路由；
- **总控不替它跑 QA，也不替它改稿。**

## 六、失败与重路由

| 失败 | 处理 |
|---|---|
| 主技能入口缺失/依赖不可用 | 匹配阶段就淘汰，换备选；不硬跑 |
| V0 不可用 | V1 只做表面去味；明确“未做防御性叙事重构” |
| V0e 不可用 | 英文改用 V1 做表面去味；明确“未做英文叙事重构” |
| V2 不可用 | 中文散文改用 V1；明确“非最小编辑路线” |
| V1 不可用 | 中文散文改用 V2；英文/平台/评分场景报告能力缺口 |
| 语言不匹配 | 换对应语言变体；不把翻译硬塞进本管线 |
| 子技能新增了原文没有的事实/细节 | 拒绝交付；带“必须保留”清单退回同一技能；再犯则停止 |
| 子技能删掉真实局限/相反证据/风险提示 | 拒绝交付；退回重做；再犯则停止 |
| 子技能把学术正文改得过度口语化 | 带“保持学术语域”约束退回；再犯则停止 |
| 用户要求绕过 AI 检测/降重/查重 | 停止；说明不支持，只提供自然表达/作者声音 |
| 正式法律/合规/合同文本要求“更像人” | 不强行人感化；只做必要的防御性表述调整或转出 |
| 所有技能都不匹配 | 停止，报告能力缺口与建议补齐的技能；不自己造流程 |

## 七、冲突裁决

- **防御性 vs 完整性**：完整性优先。防防御性写作只调整“先说什么、把什么放主线、主张收多窄”，**不能删真实局限、相反证据、风险提示或法律声明**。
- **AI 味 vs 学术语域**：学术语域优先。去 AI 味不等于口语化；术语、被动、名词化和正式连接词可以保留。
- **人感 vs 正式文本**：正式文本优先。法律、合规、合同、公文不为了“人感”牺牲准确性、效力或分寸。
- **最小编辑 vs 深度重构**：用户说“只改表达/不要动结构” → V2；用户说“故事心虚/重点错了/实验像流水账” → V0/V0e。
- **中文 vs 英文**：语言是硬约束；中文走 V0/V2，英文走 V0e/V1。
- **点名冲突**：点名优先，但语言/文本类型/完整性/目标硬约束更高；冲突时说明并让用户二选一。
- **检测规避 vs 技能范围**：检测规避不是本管线目标；直接停止，不包装成“自然化”。

## 八、自检与更新（只保协同可用）

- **自检**：`python scripts/doctor.py` 检查 registry schema、入口、关键文件、Junction 与前端名称；`--json` 输出机器可读结果。
- **更新**：`python scripts/update.py` 对 registry 里所有 git-backed 子技能执行 `git pull --ff-only`，打印变更并自检；非 git 技能会明确提示“手动更新”，不会假装已更新。
- **不缓存流程**：每次调用前 Read 子技能 `SKILL.md` 全文。
- **只改能力地图**：子技能改流程不改总控；只有能力边界/入口/依赖变化才改 `registry.json`。
- **禁止复制**：子技能只存在一份；豆包只放指向 zcode 入口的 Junction。`doubao-human-signal` 是豆包内置技能，直接读内置入口，不复制。

## 九、示例

- “这篇论文摘要读起来很心虚，帮我改得有底气，别像 AI 写的” → V0 重构叙事 → V2 最小编辑。
- “英文论文结论总是自我否定，还一股 AI 味” → V0e → V1。
- “审稿回复太防御，像在替审稿人骂自己” → V0/V0e；需要语气适配再接 V1。
- “实验部分写成流水账，重点全被淹了” → V0/V0e；结构改完再做表面编辑。
- “这段中文全是空话和模板句，保留信息删掉套话” → V2。
- “小红书文案太像 AI，帮我诊断并改得像真人” → V1。
- “先给我一套 prompt，之后写作别再一股 AI 味” → V1 上游防御。
- “帮我把这段改成能过 AI 检测” → 停止；只提供自然表达/作者声音，不承诺检测结果。
- “把这段翻译成英文” → 不归本技能，走翻译/语言技能。
- “这段合同条款太生硬，改得像人说的话” → 不归本技能；正式文本不强行人感化。
- “我不知道该用 anti-defensive 还是 humanizer” → 本技能匹配后直调。

## 十、硬规则

1. 总控不改写、不做评分、不列禁用词、不跑准出检查。
2. 硬约束（语言/文本类型/完整性/目标）优先于成熟度、偏好和点名。
3. 同一文本同一时间只有一个生产者；诊断者只出问题清单。
4. 每次调用前 Read 子技能 `SKILL.md` 全文，不凭记忆。
5. 交接必须给原文/绝对路径与“必须保留”清单；禁止让下一棒猜。
6. 子技能的 QA 是唯一质量事实源；总控只确认它跑过并记录。
7. 返修最多 3 轮；仍不过就报告能力缺口，不无限循环。
8. `stars`/成熟度只是参考，不替代专精度与可用性。
9. 不把子技能流程抄进总控；总控只存能力地图与协同规则。
10. 不编造事实/细节，不删真实局限，不承诺 AI 检测通过；任何降级都要写明“换了哪个技能、为什么、产物差异是什么”。
