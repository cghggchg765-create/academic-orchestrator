# MM Self Review — 自检评审规范

## 🔴 加载资格与委托守则（必须读）

本技能是 **评审（reviewer）子代理** 的专项规范，**仅供 `reviewer` 子代理加载执行**（论文评审 / 节点审阅 / 通用代码审查）。

- 若你是主对话主 agent：需要给论文/节点产物评审打分时，**不得直接加载本技能做"自评"**——评审必须由独立 reviewer 子代理通过 Agent 工具（`subagent_type=reviewer`）派发执行，保证执行-审阅分离。
- 主对话加载本技能自评后自己修改 = 违规（审阅 ≠ 执行，自审失真）。
- reviewer 只报告不修改；问题清单交给对应执行子代理（writing/coder 等）返修。

国赛(CUMCM)数学建模论文的自检评审标准。**统一五维口径**（假设15/创造性25/结果30/表述20/格式10），与 `mm-iteration-engine` 论文环评分体系一致（归一化 0-10，硬上限+仲裁），由 `reviewer` 论文评审模式执行。

## 国赛评审 Checklist（五维度完整版）

> **权重（与 termination.paper 与 reviewer.md 五维一致）**：假设15% / 创造性25% / 结果30% / 表述20% / 格式10%。每个维度评分精确到 0.1，归一化 0-10；综合分 = Σ(维度分 × 权重)。
> **入门门禁 W2 ≥ 6.0**（阻塞进 N8 终审）；**迭代达标线**：`termination.paper` 的 pass 6.5 / target 7.5（默认 ≤4 轮）。

### 维度一：假设合理性（权重 15%）

| 检查项 | 是 | 否 | 备注 |
|-------|:--:|:--:|------|
| 1.1 假设列表完整（无遗漏关键假设） | | | |
| 1.2 每条假设有明确的物理/逻辑依据 | | | |
| 1.3 假设不过于理想化（不影响模型实用性） | | | |
| 1.4 假设对结果的影响已说明 | | | |
| 1.5 假设之间无矛盾 | | | |
| 1.6 假设与实际问题的简化需求匹配 | | | |

**评分标准（0-10 锚点）**：
- 9-10 优秀：假设完整、合理、有依据，每条都有解释并说明影响
- 7-8 良好：假设基本合理，少量遗漏但不影响主体
- 5-6 及格：假设不够明确，部分缺乏依据
- 3-4 偏差：假设过多过强或缺少关键假设
- 0-2 较差：假设严重脱离实际

### 维度二：建模创造性（权重 25%）

| 检查项 | 是 | 否 | 备注 |
|-------|:--:|:--:|------|
| 2.1 模型有针对性（非万能模板套用） | | | |
| 2.2 有模型对比或组合创新 | | | |
| 2.3 对经典方法做了适应性改进（结合 `state/cases/` 优秀案例的 case_refs 证据） | | | |
| 2.4 创新点在论文中突出展示 | | | |
| 2.5 模型选择与问题特征匹配 | | | |
| 2.6 求解算法合理且高效 | | | |

**评分标准（0-10 锚点）**：
- 9-10 原创性强，方法巧妙，有独到见解或创新组合（含 case_refs 借鉴与改进）
- 7-8 模型合理，方法恰当，有一定特色
- 5-6 模型常规，方法套用，缺乏特色
- 0-4 模型简单粗糙，方法选择不当

### 维度三：结果正确性（权重 30%）

| 检查项 | 是 | 否 | 备注 |
|-------|:--:|:--:|------|
| 3.1 代码运行无报错（与 `Code/output/` 一致） | | | |
| 3.2 输出结果数量级合理 | | | |
| 3.3 论文数据与代码输出一致 | | | |
| 3.4 有灵敏度/敏感性分析（`ModelDocs/sensitivity-analysis.md`） | | | |
| 3.5 有鲁棒性/稳定性检验（`ModelDocs/model-validation.md`） | | | |
| 3.6 多方法交叉验证 | | | |
| 3.7 误差分析充分（`ModelDocs/error-analysis.md`） | | | |
| 3.8 结果可视化清晰（`ResultFigures/` + figure-list.md） | | | |
| 3.9 数据来源分类正确（赛题自带/外部公开/模型仿真/问卷实测），没有把仿真结果伪装成公开数据 | | | |
| 3.10 外部公开数据有机构/数据集/日期或访问时间、正文引用、GB/T 7714 条目和支撑材料；内部路径未泄露到论文 | | | |
| 3.11 🔴 图-文-数据三方一致：图由算法实际输出完整记录绘制；坐标轴范围覆盖正文声称范围（正文 K=150 → 横轴 0~150），片段图必须标注"前 N 代/局部"；正文声称的重启点/阈值在图中可见且位置正确；图例项数与曲线数、正文术语一致；点行数与输出一致 | | | |

**评分标准（0-10 锚点）**：
- 9-10 结果正确完整，验证充分，数值可信
- 7-8 结果基本正确，验证较充分
- 5-6 结果有小错误或验证不充分
- 0-4 结果明显错误或无法验证

### 维度四：表述清晰性（权重 20%）

| 检查项 | 是 | 否 | 备注 |
|-------|:--:|:--:|------|
| 4.1 摘要完整（问题+方法+结果+关键词），每问 ≥1 数字 | | | |
| 4.2 论文逻辑链条连贯 | | | |
| 4.3 每节有清晰的引入和总结 | | | |
| 4.4 图表连续编号且有标注（`figure-list.md` 与正文 `\ref{}` 一致） | | | |
| 4.5 公式连续编号且交叉引用（`\eqref{}`） | | | |
| 4.6 参考文献格式统一（GB/T 7714，**英文文献占比 ≥ 30%**） | | | |
| 4.7 符号表完整且前后一致 | | | |
| 4.8 语言流畅，无明显语法错误 | | | |
| 4.9 CUMCM 2026 profile：PDF 第4页起正文≤30页，摘要≤1页，附录不限；以导出 PDF 实页数计，禁止目录 | | | |
| 4.10 附录代码有注释 | | | |
| 4.11 正文无评审/对照元语言（"与获奖论文一致"、"作者计算"、"获奖论文参数矛盾"、"与参考结果对比"等） | | | |
| 4.12 无 AI 味段式（段落不以"黑体关键词+冒号+句子"开头；无段前手写编号 (1)/①②） | | | |
| 4.13 图表之间均有过渡叙述（无表-表/图-表紧贴）；图表标题规范（表题表上方居中、图题图下方居中、"图N 对象+内容"） | | | |
| 4.14 模型缺点/改进方向写成连贯段落（论点+依据+影响），无“序号+一句话”机械罗列 | | | |
| 4.15 图题/表注不含内部文件路径、canonical 等工程黑话；数据来源为简短学术注释 | | | |
| 4.16 分片审阅只覆盖 manifest 指定章节/小节/问题，报告含 scope_id、位置、evidence；不以整篇泛评替代局部核对 | | | |
| 4.17 内容修订与内容复审全部通过后才允许排版修订；排版后有重新构建和反向复审记录 | | | |
| 4.18 可视化遵循“需求+模型+数据→学术方案检索→方案定型→绘图”，MCP 检索和方案卡片有留痕 | | | |
| 4.19 表注/图注“少而精”：同源数据仅首次或正文统一说明一次；无“完整代码见附件、按式复核、逐条明细见独立附件、不在本文重复”等重复/内务话术；多数图表可无来源字样 | | | |
| 4.20 论文不出现外部/内部过程语言（迭代轮数、版本、修改前后对比及内部对比表）；内部记录只在 state/reports 与 git | | | |

**评分标准（0-10 锚点）**：
- 9-10 结构严谨，语言流畅，图表规范
- 7-8 表述较清晰，结构合理
- 5-6 表述不够清晰，结构有待改善
- 0-4 表述混乱，图表缺失或不规范

### 维度五：格式规范性（权重 10%）

| 检查项 | 是 | 否 | 备注 |
|-------|:--:|:--:|------|
| 5.1 LaTeX 可编译（`xelatex → bibtex → xelatex → xelatex` 链无错误） | | | |
| 5.2 页数合规（PDF 第4页起正文≤30，摘要≤1页，附录不限；PDF ≤20MB，支撑材料包≤20MB且分离） | | | |
| 5.3 引用格式统一（GB/T 7714，中英文混排正确） | | | |
| 5.4 图表/公式/表 编号连续且与正文交叉引用一致 | | | |
| 5.5 模板格式符合 CUMCM 提交要求（PDF + 附录 + 数据 + 代码） | | | |
| 5.6 hyperref 显式设色（citecolor/linkcolor 非默认绿色；编译后引用 `[1]` 非绿） | | | |
| 5.7 符号说明精简（无叙述性文字混入、无重复符号、分组 ≤ 4） | | | |
| 5.8 表注规范（"注"在 table 环境内、`\end{tabular}` 后、左对齐 footnotesize、与表体留 3-6pt 间距；不在 tabular 行内、不罗列内部文件） | | | |
| 5.9 图表不早于所属章节标题且不早于首次引用；图表不远离其首次引用文段（引导句所在页或相邻页）；符号说明标题与符号表顺序正确 | | | |
| 5.10 初轮 reviewer/linter 只读审阅可并行，任何共享文件写入均按内容→排版串行；scope 报告无空返回 | | | |
| 5.11 页码在页脚中部阿拉伯数字且摘要页起编号；承诺书/编号页不编号 | | | |
| 5.12 表格行按真实数据实体组织（无凑对齐空行/虚行/机械同列数） | | | |

**评分标准（0-10 锚点）**：
- 9-10 完全规范，无任何 LaTeX 警告
- 7-8 基本规范，少量可忽略警告
- 5-6 有少量格式问题需修正
- 0-4 编译错误或重大格式缺陷

## 硬上限与仲裁（与 mm-iteration-engine §9.3 对齐）

**硬上限**（综合分取"加权值"与"规则值"较低者）：
- 结果正确性 < 5 → 总分 ≤ 5.5
- 建模创造性 < 3 → 总分 ≤ 4.0
- 任一维 < 3 → 总分 ≤ 4.0
- 两维及以上 < 5 → 总分 ≤ 5.0

**极差仲裁**（多评审人同维度极差）：
- ≥ 4.0 → 取中位数并标记 `[ARBITRATED]`
- 2.0-3.9 → 加权平均标记 `[SPLIT]`

**verdict**：
- 综合分 ≥ pass（默认 6.5）→ PASS（达标）
- 综合分 ≥ target（默认 7.5）→ 触发 round-decide early_stop
- 否则 FAIL，附下一轮 feedback

## 去 AI 化检查清单

识别 AI 生成文本的常见模式，进行针对性修改：

### 用词模式检查

| # | AI 常见用词 | 替换建议 | 严重度 |
|---|-----------|---------|:------:|
| 1 | "值得注意的是" / "it is worth noting" | 直接陈述事实 | 高 |
| 2 | "至关重要" / "crucial" | 改用具体描述 | 高 |
| 3 | "深入探讨" / "delve into" | 用"分析"/"研究" | 高 |
| 4 | "总而言之" / "in conclusion" | 直接写结论 | 中 |
| 5 | "首先...其次...最后..." | 减少机械排列 | 中 |
| 6 | "随着...的发展" | 直接切入主题 | 中 |
| 7 | "本文旨在" / "this paper aims to" | 用"本文"开头 | 低 |
| 8 | "综上所述" | 改用具体结论 | 低 |
| 9 | "delve / leverage / robust / nuanced" 等英文 AI 高频词 | 改用平实表达 | 中 |

### 结构模式检查

| # | AI 写作模式 | 检查方法 | 修改建议 |
|---|-----------|---------|---------|
| 1 | 段落长度均匀（每段4-5句） | 统计段落句数 | 增加长短变化 |
| 2 | 列表/要点过多 | 检查列表密度 | 改用叙述性段落 |
| 3 | 过渡词机械化 | 搜索"此外""另外" | 减少过渡词 |
| 4 | 每节开头都是概述 | 检查节首句 | 直接进入内容 |
| 5 | 结论与摘要高度重复 | 对比两处文字 | 摘要写方法，结论写思考 |

### 数学建模特有检查

| # | 检查项 | 说明 |
|---|--------|------|
| 1 | 公式是否有手写推导过程 | AI 常直接给结果跳过推导 |
| 2 | 模型假设是否与实际问题对应 | AI 常写通用假设 |
| 3 | 数据分析是否有具体的数值结论 | AI 常给定性描述 |
| 4 | 图表是否来自实际代码运行（与 `Code/output/` 对齐） | AI 常编造图表数据 |
| 5 | 代码是否能实际运行出结果 | AI 代码常有隐含错误 |

## 自检流程

```
Step 1: 运行五维度 Checklist（每个维度独立评分 0-10）
         ↓
Step 2: 应用硬上限（任一维 < 3、两维 < 5、结果<5、创造性<3 → 降总分）
         ↓
Step 3: 多评审人时极差仲裁（极差 ≥ 4.0 取中位数 ARBITRATED）
         ↓
Step 4: 计算综合分 = Σ(维度分 × 权重)
         ↓
Step 5: 与 termination.paper 阈值比对：W2 ≥ 6.0 / pass 6.5 / target 7.5
         ↓
Step 6: 运行去AI化检查清单
         ↓
Step 7: 汇总问题清单 + 修改优先级矩阵
         ↓
Step 8: 输出评审报告（落盘 state/agents/reviewer/result.json + 节点首页"审阅记录"区 + node-review 门禁 W2）
         ↓
Step 9: FAIL → 携 feedback 进入下一轮；达标 → 落 S<n>-N7 门禁 PASS，round-decide 决策（early_stop / pass_continue / keep_best）
         ↓
Step 10: 按优先级修改后重新评审（Re-Review 衔接）
```

## Anti-Patterns

| # | 反模式 | 后果 | 正确做法 |
|---|--------|------|---------|
| 1 | 评审走过场 | 问题遗漏 | 逐项过 Checklist |
| 2 | 只看总分不看分项 | 找不到薄弱环节 | 分维度独立评分 |
| 3 | 评审完不修改 | 浪费评审时间 | 按优先级逐项修改 |
| 4 | 修改后不复审 | 引入新问题 | 修改后重新评审（Re-Review） |
| 5 | 忽略去AI化 | 评阅印象差 | 专项检查AI模式 |
| 6 | 用四维度 20/25/30/25 旧口径 | 与 reviewer/mm-iteration-engine 五维体系漂移 | 统一用五维 15/25/30/20/10 |
| 7 | 不读上游产物（formula.md / DataLog.md / figure-list.md） | 评分缺乏事实依据 | 先交叉验证再评分 |
