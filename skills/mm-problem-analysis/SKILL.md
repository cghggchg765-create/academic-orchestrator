## CUMCM 题型分类

### 五大题型速查表

| 题型 | 代号 | 典型特征 | 常用模型方向 | 典型历年题目 |
|------|------|---------|-------------|-------------|
| **连续型** | A | 连续变量、微分方程、物理建模 | ODE/PDE、优化、数值模拟 | 嫦娥轨道设计、波浪能利用 |
| **离散型** | B | 离散结构、图论、组合优化 | 图论、整数规划、排队论、博弈论 | 企业排班、网络设计 |
| **数据型** | C | 大数据集、统计分析、机器学习 | 回归、聚类、分类、时间序列 | 股票预测、用户画像 |
| **综合型** | D | 多方法融合、跨学科 | 多模型组合、系统工程 | 供应链优化、环境评估 |
| **新兴题型** | E | 新领域、交叉学科、开放性 | 视具体问题灵活选型 | 智慧城市、碳中和 |

### 题型判定决策树

```
赛题拿到后：
├─ 有大量数据文件（CSV/Excel）？
│   ├─ 是 → 侧重数据处理 → 可能是 C 或 D
│   └─ 否 → 继续判断
├─ 涉及物理过程/连续变量？
│   ├─ 是 → A 题倾向
│   └─ 否 → 继续判断
├─ 涉及网络/图结构/调度/组合？
│   ├─ 是 → B 题倾向
│   └─ 否 → 继续判断
├─ 需要多种方法综合？
│   ├─ 是 → D 题倾向
│   └─ 否 → 可能是 E（新兴）
```

## 题目原文优先与事实锁定

开始拆题前必须打开并完整阅读题目原文，记录来源和 SHA-256；禁止只根据用户转述、文件名或既有论文推断题意。拆解完成后，必须把目标、约束、前提条件、数据要求和评价指标写入 `state/problem_lock.json`，并通过 `problem_guard.py verify`。

后续 Agent 只能把该锁定文件作为任务边界：如果代码、数据或论文中的结论无法映射到锁定目标和约束，必须标记为偏移并退回 N1 重新核对。

## 评分要点速查

### 国赛评阅五维度（与 reviewer/mm-self-review/mm-iteration-engine 论文环完全统一）

国赛论文评阅围绕五个核心维度展开，权重与 0-10 归一化评分标准如下（综合分 = Σ(维度分 × 权重)，再应用硬上限与仲裁）：

#### 维度一：假设合理性（权重 15%）

| 评分档 | 标准描述（0-10） |
|:------:|-----------------|
| 9-10 优秀 | 假设明确、合理、有依据，与实际问题高度契合，未遗漏关键假设，且说明对结果的影响 |
| 7-8 良好 | 假设基本合理，有少量遗漏但不影响主体建模 |
| 5-6 及格 | 假设不够明确，部分假设缺乏依据或与实际脱节 |
| 0-4 偏差 | 假设过多过强，严重脱离实际，或缺少必要假设 |

**检查要点：**
- [ ] 每条假设都有明确的物理/逻辑依据
- [ ] 假设列表是否覆盖了所有简化条件
- [ ] 假设是否过于理想化导致模型失真
- [ ] 是否说明了假设对结果的可能影响

#### 维度二：建模创造性（权重 25%）

| 评分档 | 标准描述（0-10） |
|:------:|-----------------|
| 9-10 优秀 | 模型原创性强，方法选择巧妙，有独到见解或创新组合（结合 `state/cases/` 优秀案例的 case_refs 证据） |
| 7-8 良好 | 模型合理，方法选择恰当，有一定特色 |
| 5-6 及格 | 模型常规，方法套用，缺乏特色 |
| 0-4 偏差 | 模型简单粗糙，方法选择不当 |

**检查要点：**
- [ ] 模型是否有针对性（不是万能模板）
- [ ] 是否有多模型对比或组合创新
- [ ] 是否对经典方法做了适应性改进
- [ ] 模型的创新点是否在论文中突出展示

#### 维度三：结果正确性（权重 30%）

| 评分档 | 标准描述（0-10） |
|:------:|-----------------|
| 9-10 优秀 | 结果正确、完整，有充分验证，数值合理可信（与 `Code/output/` 一致） |
| 7-8 良好 | 结果基本正确，验证较充分 |
| 5-6 及格 | 结果有小错误或验证不充分 |
| 0-4 偏差 | 结果明显错误或无法验证 |

**检查要点：**
- [ ] 代码运行结果与论文数据一致
- [ ] 有灵敏度分析/鲁棒性检验（`ModelDocs/sensitivity-analysis.md` / `model-validation.md`）
- [ ] 结果数量级是否合理
- [ ] 是否有多方法交叉验证

#### 维度四：表述清晰性（权重 20%）

| 评分档 | 标准描述（0-10） |
|:------:|-----------------|
| 9-10 优秀 | 论文结构严谨、语言流畅、图表规范、公式清晰 |
| 7-8 良好 | 表述较清晰，结构合理，图表基本规范 |
| 5-6 及格 | 表述不够清晰，结构有待改善 |
| 0-4 偏差 | 表述混乱，图表缺失或不规范 |

**检查要点：**
- [ ] 摘要是否完整覆盖问题、方法、结果（每问 ≥1 数字）
- [ ] 论文逻辑链条是否连贯
- [ ] 图表是否有编号和清晰标注（与 `ResultFigures/figure-list.md` 一致）
- [ ] 公式是否统一编号且交叉引用

#### 维度五：格式规范性（权重 10%）

| 评分档 | 标准描述（0-10） |
|:------:|-----------------|
| 9-10 优秀 | LaTeX 可编译无警告，页数合规，引用与编号完全统一 |
| 7-8 良好 | 基本规范，少量可忽略警告 |
| 5-6 及格 | 有少量格式问题需修正 |
| 0-4 偏差 | 编译错误或重大格式缺陷 |

**检查要点：**
- [ ] LaTeX 编译链 `xelatex → bibtex → xelatex → xelatex` 无错误
- [ ] CUMCM 2026 profile：PDF 第4页起正文≤30页，摘要≤1页，附录不限；以导出 PDF 实页数核对
- [ ] 引用格式 GB/T 7714，英文文献占比 ≥ 30%

## 硬上限（与 mm-iteration-engine §9.3 对齐）

- 结果正确性 < 5 → 综合分 ≤ 5.5
- 建模创造性 < 3 → 综合分 ≤ 4.0
- 任一维 < 3 → 综合分 ≤ 4.0
- 两维及以上 < 5 → 综合分 ≤ 5.0

## Pro 知识库融合（v1.7.0）：题型诊断与子问题依赖

> 融合自 math-modeling-skill-pro（作者授权）：139 篇 CUMCM 优秀论文（2012—2025）提炼的赛题拆解决策规则，挂接本技能既有题型识别流程，不替代上述速查表。

### 资产位置
- `skills/mm-problem-analysis/assets/pro/problem-types.md`：六维结构诊断（目标/数据/关系/结构/决策/不确定性）、主类型速查、复合问题与易混类型、题目识别操作表
- `skills/mm-problem-analysis/assets/pro/problem-dependencies.md`：子问题依赖图、依赖边类型、误差传播、交付模板
- `skills/mm-problem-analysis/assets/pro/templates/problem-analysis.md`：赛题分析模板（赛题指纹/假设台账/候选路线）

### 使用时机
N1 选题拆解输出前必须完成：①证据边界 → ②每个子问「输入—决策—输出—判据」→ ③依赖图（串联/分支/汇合/反馈/分层/情景）→ ④题型诊断 → ⑤`state_utils.py case-search` 案例类比检索（见主控 Phase 1）→ ⑥A/B/C 候选路线。

### 与既有流程的关系
- 本技能已有的题型速查/拆解清单负责「按关键词快速分类」；Pro 资产提供「反证门槛」——每个子问必须给出「不是该类型」的证据，防止关键词机械匹配。
- 依赖图要求：仅当下游确实使用上游产物才连边；共享原始数据不自动形成依赖；上游误差必须标注传播方式（区间/分位数/情景），不能只传均值。
- 交付到 ProblemInfo/ 时附依赖表 + 每子问一条识别记录（question_id/verbatim_goal/output_object/…）。

### 回退
Pro 资产与既有表格冲突时以既有表格为准；缺失信息写「待补」并降低结论强度，禁止虚构。
