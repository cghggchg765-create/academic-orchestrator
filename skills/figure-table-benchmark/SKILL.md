# 图表与表格文献对标规范

## 为什么需要这一层

常规图表审阅只回答「这张图/表**合规吗**」（分辨率、编号、三线表、数据同源）。
它回答不了另一个问题：**同行在这个问题上会放什么，我们是不是漏了？**

典型漏项：别人给一列的置信区间我们没给；别人表格有「样本量 / 单位 / 缺失率」列我们没有；
别人把主结果与消融拆成两张表，我们塞成一张导致列义混淆；别人图给了基线与 SOTA 参照我们只有自比。

本 skill 定义**对标**这件事怎么做、判什么、怎么留证。判定对象是**完备性与学术性**，不是格式合规。

## 一、什么时候必须做对标

| 场景 | 是否强制 |
|---|---|
| N6 结果可视化定稿前 | ✅ 强制（新建图/大改图时） |
| N7 论文写「结果」「实验」「对比」章节前 | ✅ 强制（决定放哪张表、哪些列） |
| N8 终审 | ✅ 强制（复核对标矩阵是否闭环） |
| 只改图注/字号/配色 | ❌ 不必要 |
| 纯示意结构图（无数据） | ❌ 不必要 |

## 二、四步法

### 第 1 步：抽取「我们打算怎么表达」

从当前产物里抽出待判定的图/表清单（不是从零构思，而是审已有）：

```
Code/output/tables/*.csv|md        结果表原始数据
ResultFigures/figure-list.md       论文级图清单（编号/用途/对应章节）
ReportPaper/LaTeX/sections/*.tex   \begin{table} / \includegraphics 的实际用法
```

对每张图/表记录：**它想支撑哪个主张**（claim）、**当前列名/坐标轴/图例**、**当前给出的统计量**。

### 第 2 步：检索同领域论文的同类表达（本步是核心，不可跳过）

必须**实际检索**，不得凭记忆编造同行做法。检索源按可用性择用：

| 用途 | 首选 | 回退 |
|---|---|---|
| 找同题论文 | 论文搜索 MCP（paper-mcp） | WebSearch / Semantic Scholar / arXiv |
| 看具体图怎么画 | 下载 PDF 后用 `mm-pdf-vision` 逐页读图 | 读 HTML 版图注与正文描述 |
| 看表格列名 | PDF 表格区域 / 论文 LaTeX 源（若可得） | 正文「Table N reports ...」句式 |
| 找综述里的标准表述 | 综述类文章优先 | 领域顶刊的 related work |

每篇被对标论文必须记录：`{paper_id, venue, year, 图/表编号, 页/位置, 检索渠道, 检索词}`。
未记录来源的「同行做法」一律视为**编造**，不得进入判定。

### 第 3 步：建对标矩阵（核心产物）

产出 `state/reports/figure-table-benchmark/<节点>_<轮次>.json`，结构见
`references/benchmark-matrix.schema.json`，要点：

| 字段 | 含义 |
|---|---|
| `artifact_id` | 我方图/表标识（与 figure-list 一致） |
| `artifact_kind` | `figure` / `table` |
| `supported_claim` | 该图表要支撑的主张 |
| `our_spec` | 我方当前规格：图型/列名/统计量/单位/样本量 |
| `benchmarked` | 对标的同行论文清单（含来源留痕） |
| `peer_specs` | 同行在该主张上的表达规格（合并去重后的并集与交集） |
| `dimensions` | 逐维度判定，见下表 |
| `gaps` | 我方缺失项（每条须指向具体同行证据） |
| `verdict` | `COMPLETE` / `GAP_MINOR` / `GAP_MAJOR` / `BLOCKED` |

**判定维度（七维，逐项都要给证据）**：

| # | 维度 | 判什么 | 常见缺陷 |
|:-:|---|---|---|
| 1 | 数据列完备 | 同行必给的列/轴，我方是否都有 | 缺置信区间、缺基线、缺样本量 |
| 2 | 统计量完备 | 中心量/离散量/显著性/效应量是否齐 | 只有均值无误差、有 p 无效应量 |
| 3 | 单位与量纲 | 每列/每轴是否标单位、单位是否统一 | 单位散落在正文、图表内混单位 |
| 4 | 可比性锚点 | 是否给出可横向对比的参照（基线/SOTA/上界） | 只有自比、无外部参照 |
| 5 | 分组与层级 | 分组维度是否与主张一致、是否漏掉关键分层 | 把异质子集合并成一行 |
| 6 | 图型恰当性 | 图型是否匹配数据类型与主张（对照同行选择） | 分布数据用均值柱、双 Y 轴 |
| 7 | 学术表达规范 | 列名/轴标签是否学术化、有无口语化或内部代号 | 列名写 `p1_out`、轴标 `结果` |

**判定口径**：
- `COMPLETE`：七维全有证据支撑，无 gap；
- `GAP_MINOR`：仅维度 3/6/7 类问题，不影响结论成立；
- `GAP_MAJOR`：维度 1/2/4/5 任一缺失 —— **会导致结论强度被高估或信息不足，必须修**；
- `BLOCKED`：无法完成检索（无可用检索源或无对标论文），如实标记，**不得伪装 COMPLETE**。

### 第 4 步：回传与闭环

- `GAP_MAJOR` → 回传 `visualization`（图）或 `writing`（表）补数据/补列，补齐后重新对标；
- `GAP_MINOR` → 记入待办，可在排版阶段一并处理；
- `BLOCKED` → 主 Agent 决定是否降级（如换检索源），并在 `state/state_utils.py node-log` 留痕；
- 闭环证据：`state/reports/figure-table-benchmark/` 下矩阵 + `state/agents/<agent>/result.json` 的 `benchmark_refs` 字段。

## 三、硬约束（违反即判定无效）

1. **不得凭记忆编造同行做法**：每条 `peer_specs` 必须能追到 `benchmarked` 里某篇的 `{页/位置, 检索渠道}`。
2. **不得用「我认为应该」替代「同行实际这么做」**：主观建议只能写进 `notes`，不得进 `gaps`。
3. **不得因「改起来麻烦」把 GAP_MAJOR 降级为 GAP_MINOR**：维度 1/2/4/5 缺失就是 MAJOR。
4. **不得只对标 1 篇**：至少 3 篇同领域论文，否则 `verdict` 最高只能到 `GAP_MAJOR`（样本不足）。
5. **不得跳过表格**：表格与图同等重要；表格列名是最常被漏检的完备性问题。

## 四、与既有审阅的分工

| 角色 | 负责 |
|---|---|
| `mm-viz-reviewer` | 格式规范、数据同源、图-文-数据三方一致（V1 门禁的 20 项） |
| `mm-figure-table-benchmarker` | 本 skill 的对标方法与矩阵产出（完备性/学术性判定） |
| `reviewer` | 论文层内容与证据审阅（N7/N8） |

**互不替代**：格式全合规但缺关键列的表格，V1 可能 PASS，但对标必须报 `GAP_MAJOR`。

## Anti-Patterns

| # | 反模式 | 后果 | 正确做法 |
|:-:|---|---|---|
| 1 | 只看 1-2 篇就下结论 | 结论不成立 | ≥3 篇同领域 |
| 2 | 把「同行没写」当作「我们也不用写」 | 漏掉领域惯例 | 以交集为底线、并集为上限 |
| 3 | 矩阵只写结论不写证据位置 | 无法复核 | 每条 gap 附页码/检索渠道 |
| 4 | 只对标图不对标表 | 表格列名缺陷漏检 | 图/表各建矩阵条目 |
| 5 | 检索失败仍标 COMPLETE | 伪造完备性 | 标 BLOCKED 并升级 |
