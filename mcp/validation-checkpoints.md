# MCP 闭环校验检查点（独立专属）

> 四个检查点串起"MCP 从启动到交付"的完整闭环。任一检查点不通过即阻断对应阶段。

## 1. 启动检查点（Checkpoint 0）

- **条件**：① 全局 MCP 扫描 → ② 筛选 → ③ 内嵌封装 → ④ 自检，全部通过。
- **判据**：`scripts/mcp_boot_check.py --report` 输出 `MCP_READY`。
- **不通**：任何建模任务不得启动，输出异常 MCP 名称，修复后重跑。

## 2. 调研检查点（N1 选题 / N3 建模 前置）

- **论文搜索 MCP**：文献归档案（分支 A 原文 / 分支 B 国标条目）完整合规——`state/reports/references-ledger.md` 台账已建立且含本项目已检索文献全量 GB/T 7714 条目；
- **Tavily / 论文搜索**：N1 案例调研知识卡片 ≥ 对应卡片模板要求（来源、依据、引用齐全，无空卡）。
- **不通**：N1/N3 不视为调研完成，禁止进入模型选型 / 方案定稿。

## 3. 建模工程检查点（N3 / N4 / N5 / N6 / N7）

- **核心节点 MCP 必调记录完整**：对照 `call-hierarchy.md` 六节点表逐项核对调用留痕（`state/reports/mcp-calls.jsonl` 或 handoff）；
- **Context7 / GitHub 检索的优化方案有效支撑模型与代码性能优化**：N4 代码提交中可追溯到所依据的文档/源码来源（知识卡片），无"无来源的冷代码"；
- **无跳过、无内生自研内容**：核心产物（模型文档、代码、算法）不得凭空内生，必须依托 MCP 检索依据。

### N6 可视化前置检查（🔴 先模型与数据，再检索方案，再绘图）

- 模型与数据已确认：存在对应 `ModelDocs`、`Data` 或 `Code/output` 证据，且可视化清单标明展示目的、数据字段和数据分类；
- 绘图前已调用论文搜索 MCP + Tavily/WebSearch（不确定绘图库 API 时补 Context7），并在 `state/reports/mcp-calls.jsonl` 留痕；
- 检索结果已沉淀到 `state/reports/mcp-cards/`，候选方案比较和最终图形定型记录可追溯；
- 数据来源分类为 `contest_provided` / `external_public` / `model_simulation` / `survey_field`，图表注释、参考文献、支撑材料和代码要求与分类一致；
- 缺少任一项时，N6 不得进入绘图或 V1，必须返回数据溯源/学术方案检索阶段。

- **不通**：对应节点门禁（P2/T1/V1/W2 等）不落盘，进入修复循环。

## 4. 终检检查点（N8 评审 / 交付前）

- **MCP 调用记录完整**：五节点必调记录逐条核对，无缺失；
- **文献归档完整**：GB/T 7714 台账与论文参考文献表一一对应（条数/内容不漂移）；
- **知识卡片资料完整**：所有核心节点检索结果均有卡片，来源/依据/引用可溯源。
- **不通**：不产出交付摘要，回到缺口节点补全。

## 闭环示意图

```
[启动检查点] → 任务启动
      ↓
[调研检查点] ← N1/N3 前置（文献台账 + 案例卡片）
      ↓
[建模工程检查点] ← N3/N4/N5/N7（必调留痕 + 有据产出）
      ↓
[终检检查点] → N8 评审通过 → 交付（记录/档案/卡片闭环）
```

## 校验命令

```bash
# MCP 启动自检（含报告文件）
python scripts/mcp_boot_check.py --report

# 调用留痕统计（五节点必调覆盖）
python scripts/mcp_boot_check.py --coverage --dir <任务目录>

# 台账完整性检查（GB/T 7714 条目非空、作者/题名/年份/DOI 齐全）
python scripts/mcp_boot_check.py --ledger <references-ledger.md 路径>
```
