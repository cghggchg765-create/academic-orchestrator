# 插件启动强制 MCP 初始化流程（Checkpoint 0｜唯一入口、必跑流程）

> **优先级：最高。** 任何数学建模任务开工前，必须先完整执行本流程 ①→④，顺序不可逆、不可跳过；任一异常即终止全部任务，修复后方可继续。

## Checkpoint 0 — MCP 全局探测与插件封装前置检查点

### 步骤 1：全局 MCP 全量扫描探测（插件启动瞬间 · 第一动作）

- 插件启动瞬间，优先执行系统**全局 MCP 全量扫描**，自动读取当前设备所有已全局安装、已注册、可调用的 MCP 完整列表（含命名空间、工具清单）。
- **以本地真实安装结果为唯一依据**：禁止虚构、禁止硬编码 MCP 列表。扫描来源优先级：
  1. 当前运行会话实际注册的 MCP 工具命名空间（`mcp__*`）；
  2. 本机 MCP 配置文件（`~/.zcode/mcp*.json`、项目 `.mcp.json`、`.codex-plugin` / `.claude-plugin` 内声明的 MCP server）；
  3. 环境变量 / 进程环境注入的 MCP 服务。
- 产出：`mcp/mcp-scan-results.md` 中"扫描结果"表，逐项记录 `MCP 服务 / 命名空间 / 工具/能力 / 状态 / 备注`。每次扫描可覆盖刷新该表底部的 `扫描时间` 与哈希指纹，但不得伪造未安装项。

### 步骤 2：筛选数学建模流水线专属四类有效 MCP

从步骤 1 的真实清单中，仅筛选以下**四类**进入插件内核（其余 MCP 不入栈，不参与建模流水线）：

| 序号 | MCP 类别 | 本机实际对应 | 服务定位 |
|:-:|---------|-------------|---------|
| 1 | 论文搜索 MCP | `mcp__paper-mcp`（paper_search / download_paper / vpn_login） | 文献检索 & 归档（核心常驻） |
| 2 | GitHub MCP | `mcp__github`（仓库/代码/PR/Issue） | 开源工程专项 |
| 3 | Context7 MCP | `mcp__context7`（resolve-library-id / query-docs） | 算法技术专项 |
| 4 | Tavily 全网搜索 MCP | Tavily 官方 MCP（**未安装**，见下方说明）；当前替代 = `mcp__tokenhub-tools` 的 `search` | 前沿资料专项 |

> **Tavily 未安装说明**：步骤 1 实测未发现 Tavily 官方 MCP 服务器。按"禁止虚构、以真实安装为准"原则，本插件将 Tavily 列为"待安装 + 自动回退"：安装配置与双轮换密钥见 `mcp/tavily-mcp.config.json`；安装完成前，全网搜索职责由 `mcp__tokenhub-tools::search`（已就绪）承担，Tavily 安装并自检通过后立即优先接管。两者都不可用时，视为 MCP 缺失 → 按步骤 4 终止。

### 步骤 3：插件内嵌封装（四类 MCP 固化至插件内核）

> “四类”表示 MCP 职责类别；“carrier”表示下列协议/门禁/模板文件，二者不是同一个数量口径。机器检查以显式文件清单为准，不再使用 4/8/10 的概数。

将筛选通过的 MCP **完整迁移、打包、内嵌、固化**至数学建模插件内核，转为**插件原生内置常驻能力**：

- **封装载体**（本插件为文件型插件，内嵌 = 以下四项全部就位）：
  1. 使用协议：`mcp/cluster-roles.md`（分工固定、不可篡改）；
  2. 调用规范：`mcp/call-hierarchy.md`（常规灵活 / 核心强制双模式）；
  3. 启动门禁：本文件 ①→④ + `scripts/mcp_boot_check.py`；
  4. 输出约束：`mcp/knowledge-card.template.md` + `mcp/reference-ledger.template.md`。
- **就绪语义**：MCP 服务随插件生命周期自动启动、自动挂载、自动就绪，无需用户手动逐项配置；用户仅需保证其已在本机安装注册（步骤 1 扫描得到）。

### 步骤 4：MCP 加载自检（异常即终止）

运行 `python scripts/mcp_boot_check.py --report`，逐项校验：

| 校验项 | 判定 |
|--------|------|
| 加载状态 | 目标 MCP 是否存在于扫描结果（命名空间 + 工具可用） |
| 调用权限 | 当前会话是否允许调用该 MCP 工具（无 deny） |
| 联网状态 | MCP 所依赖的外部服务端点能否连通（仅对可探测服务执行） |
| 密钥有效性 | Tavily 双密钥格式与健康度 / 其它需鉴权 MCP 的凭据有效性 |

- **全部通过** → 输出 `MCP_READY`，允许建模任务启动；
- **任一异常/缺失/加载失败/调用报错** → 输出 `MCP_BLOCKED`，**立即终止所有任务**，精准提示异常 MCP 名称与修复路径；修复后重跑自检，通过方可放行。

## 铁律

1. ①→④ 顺序不可逆、不可跳过；禁止"跳过自检直接开工"。
2. 扫描结果必须来自本地真实清单，禁止虚构/补造 MCP。
3. 核心节点执行时按 `call-hierarchy.md` 强制调用 MCP，禁止纯内生输出、禁止主观臆造（详见该文件）。
4. 自检失败时，未修复前任何建模节点（N1-N8）不得启动。
