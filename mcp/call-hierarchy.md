# MCP 调用层级规则（双模式锁定）

> 灵活按需调用 + 关键节点强制必调，两种模式并存：**常规任务按需灵活，核心关键节点强制 100% 必调（不可跳过、不可省略）**。

## 一、常规任务：按需灵活调用

日常辅助梳理、文字润色、基础信息查询、常规内容补全类任务，AI 可根据实际任务需求自主判断是否调用对应内嵌 MCP，无需强制触发，灵活适配任务轻重。

## 二、核心关键节点：强制 100% 必调（不可跳过、不可省略）

以下建模核心环节，无论任务场景如何，**必须调用对应 MCP 获取外部权威资料支撑，禁止纯内生输出、禁止主观臆造**：

| # | 建模核心环节 | 对应节点 | 必调 MCP | 用途 |
|:-:|------------|---------|---------|------|
| 1 | 问题深度分析、同类建模案例调研 | N1 选题拆解 | **论文搜索 MCP + Tavily 全网搜索 MCP** | 赛题背景、同类案例、前沿资料 |
| 2 | 数学模型选型、算法架构设计 | N3 模型搭建 | **Context7 MCP + 论文搜索 MCP** | 模型原理、公式细节、方法依据文献 |
| 3 | 代码编写、算法性能优化、速度提速、资源降载迭代 | N4 代码开发（迭代环） | **Context7 MCP + GitHub MCP** | API 文档、开源实现、高性能算法 |
| 4 | 实验仿真、结果校验、稳健性优化 | N5 模型调优 | **GitHub MCP + Tavily 全网搜索 MCP** | 开源基线对照、SOTA / 前沿优化算法 |
| 5 | 论文参考文献整理、国标归档、文献补全 | N7 论文撰写 | **论文搜索 MCP** | 检索文献、双分支归档、GB/T 7714 台账 |
| 6 | 可视化方案选型（模型与数据已确定后） | N6 图表 | **论文搜索 MCP + Tavily/WebSearch；不确定绘图库 API 时补 Context7** | 检索同类学术图表方案、可读性/编码方式/子图布局依据；确定方案后才绘图 |

> 支撑性必调：文献综述 / 引证（N7 前置）→ 论文搜索 MCP；数据源发现（N2）→ Tavily；**可视化方案检索（N6）→ 论文搜索 MCP + Tavily/WebSearch，必须在绘图前留痕**。N8 评审对上述必调记录做"无跳过、无内生自研"校验（见 `validation-checkpoints.md` 建模工程检查点）。

## 三、强制输出约束

1. **知识卡片**：所有核心节点的 MCP 检索结果，必须结构化沉淀为知识卡片（模板 `mcp/knowledge-card.template.md`），留存来源、依据、引用信息——可溯源、可复用、可归档（落 `state/reports/mcp-cards/`）。
2. **有据编码**：算法与代码产出必须依托 MCP 检索到的优化方案，确保模型高效、高性能、低冗余；**杜绝低效、冗余、无依据的算法设计与代码实现**。
3. **必调留痕**：每次核心节点 MCP 调用记录（时间、节点、MCP、查询、结果摘要、卡片路径）统一追加写入 `state/reports/mcp-calls.jsonl`（机器事实源，`round-score`/`node-review` 的"禁止纯内生"门禁与 `mcp_boot_check.py --coverage`、N8 终检都读它）；`handoff.md` 只作交接可读视图，不替代 jsonl 留痕。

## 铁律
1. 核心节点未调用必调 MCP → 该节点不视为完成（N8 评审拦截）。
2. 禁止在无任何外部资料支撑下，凭记忆内生"权威方案/某论文结论"。
3. MCP 查询失败时，改词重试 ≥2 次并换备选 MCP；仍失败 → `[ESCALATE]` P1，不得静默跳过。
