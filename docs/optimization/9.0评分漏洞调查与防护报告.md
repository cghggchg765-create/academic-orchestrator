## 2. 根因（五层）

1. **引擎断层（根）**：项目运行时（8/18）插件尚未完成 1.5.0 门禁强化/安装，评审走的是旧副本（无前缀 `reviewer` + 无版本 skills_read）。旧引擎没有：MCP 必调强制、知识卡片要求、executor result.json 证据、H 门禁一致性、评审对象时间戳校验。对旧引擎，"违反所有规则"不成立——**规则在旧引擎里不存在**。
2. **评审对象漂移**：9.0 评的是 8/18 的中间稿；8/19 论文又构建了最终版，9.0 结论却原样保留——无"评审快照 vs 最终产物"时间线校验。
3. **人工在环缺位**：H3 pending 未阻断节点完成推进；H1/H2 被旧引擎 `auto_passed` 直接放行（新引擎语义为"待人工追认"，但旧引擎无追认流程）。
4. **执行派发绕过**：N6 无 executor result.json——主 agent 内联代做，无独立执行痕迹。
5. **证据体系缺失**：无 N7 卡片、无 deAI 报告、mcp-calls 台账不完整——旧引擎没有这些概念，无从检查。
