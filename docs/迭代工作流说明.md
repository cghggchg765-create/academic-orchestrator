# 迭代工作流说明（状态统一节点 + 节点独立执行 + 专用审阅 + 插件适配）

> 面向团队的使用说明。机器可读规范见 `skills/mm-iteration-engine/SKILL.md`，主控流程见 `skills/mathematical-modeling/SKILL.md`。

## 1. 一句话总览

每个竞赛项目在初始化时按标准结构（MathModel_Contest）搭建，并在 `state/` 预建**外部状态统一节点**（全局状态 + 总状态工作栏 + 9 个节点单独首页 + 调用路由注册表）。任何节点（选题/数据/建模/代码/调优/图表/论文/评审）都可以**单独调用**——节点 Agent 自治联动（检查前置→执行→自检→配对审阅→修复→交付），代码与论文节点则跑**迭代循环**：搜索优秀案例 → 实现 → 运行 → 分支提交 → 多维评分 → 未达标继续下一轮。

## 2. 状态统一节点（state/）

```
state/
├── decision_log.json       # 全局状态（schema 2.0）：stages/nodes/gates/rounds/decisions/termination/meta
├── dashboard.md            # 总状态工作栏（9 节点卡片 + 门禁 + 待办）
├── registry.json           # 调用路由注册表（任务→执行/审阅 Agent→必读 Skill→门禁→产物）
├── search_sources.json     # 检索地址注册表（SEARCH 网络搜索源，7 个默认渠道）
├── problem_lock.json       # 题目事实锁定（原文 SHA-256 + 目标/约束/数据/指标）
├── compatibility_manifest.json  # 已有材料接入清单（来源/目标/哈希/转换状态）
├── source_inventory.md     # 代码、数据、论文对应关系清单
├── claim_evidence_map.json # 论文主张 ↔ 运行证据/数据字段/图表映射
├── state_utils.py          # 状态节点命令行助手（init 时复制，项目自包含）
├── human_checkpoint.md     # 人工在环挂起记录（H1/H2/H3）
├── latex_conversion/       # Markdown/PDF → LaTeX 转换任务（document_to_latex，BLOCKED 待专用 Agent）
├── cases/                  # 优秀案例库（SEARCH 沉淀，跨轮复用）
├── reports/                # 迭代报告留存（review/decision/result 自动归档 + index.json，跨轮复读对比）
├── agents/<id>/            # 各 Agent 唯一写回点 result.json + 租约 claim.json
└── nodes/                  # 9 个节点单独首页（初始化预建，全部 pending）
```

**铁律**：orchestrator 是全局文件的唯一写者；子 Agent 只写自己的 result.json；写入原子替换；每次状态变更单独 git commit；初始化时全量预建（属前期工作），之后只跑中间节点也只刷新对应首页。

## 3. 标准项目结构与产物落点

初始化命令（由 orchestrator Phase 0 执行）：

```bash
python state/state_utils.py init --dir <项目目录> --name CUMCM --year 2026 --problem A --language zh --git
```

**题目 PDF 图形处理（读题前置）**：题目含图形时，在锁定题目事实前先处理图形——

- 模型有视觉能力：`python state/problem_guard.py figures --project . --source <题目PDF> --mode vision` → PDF 逐页渲染为 `ProblemInfo/figures/page-*.png`（需 pdftoppm；无工具时返回 BLOCKED 提示）→ 视觉模型逐页阅读图形 → `figures-read --mode vision` 登记；
- 模型无视觉能力：`figures --mode human` → 生成 `state/problem_figure_request.md` 请求单 → 发人工详细描述 → `figures-read --mode human --description "<描述>"` 登记；
- 无图形：`create --figure-mode none`（默认）。

`problem_guard.py verify` 会强制校验图形已处理（vision 需图片+已阅读；human 需人工描述），未完成前 N1 及之后节点不得开工。详细命令见 `mathematical-modeling` SKILL 的"题目 PDF 图形处理"节。

生成 MathModel_Contest 标准结构。产物落点映射：

## 4. 单独调用某个节点（节点自治联动）

例如只跑"代码迭代"（假设项目已初始化）：

1. 用户说"帮我迭代第一问的代码" → orchestrator 读 `state/decision_log.json` + N4 节点首页 + registry。
2. coder 自治：读状态 → 写 claim 租约 → **前置联动检查**（`formula.md` 缺失则委派 modeler 补跑，或输出 `[PREREQ-REQUEST]` 由 orchestrator 转派）→ **搜索前置**（搜索优秀案例 → `case-add` 沉淀）→ 实现 → 运行 → 自检。
3. coder 收尾：写 result.json、刷新 N4 首页、输出 `[REVIEW-REQUEST]`。
4. orchestrator 派发**专用审阅 Agent mm-code-reviewer**（先读 mm-iteration-engine + mm-algorithm-dev + code-review 三个 Skill 并声明 → 五维评分 → 落盘 + P2 门禁）。
5. FAIL → feedback 返回 coder 修复（≤2 次小循环）；PASS → 节点交付完成。

## 5. 迭代循环（代码/论文）

```
SEARCH（搜优秀案例→state/cases/）
  → SELECT（选型+记 decision）
  → IMPLEMENT（roundN 分支实现）—— state_utils.py round-start --branch round{N}_{slug} --git
  → RUN（运行+exit_code+checks）
  → COMMIT（implement/run/score 三次提交，trailer: Round/Agent/Stage/Gate/Goal/Score）
  → SCORE（mm-code-reviewer 代码五维 / reviewer 论文五维，硬上限+仲裁）—— state_utils.py round-score
  → DECIDE —— state_utils.py round-decide：
      ≥target 提前终止并 merge main / ≥pass 达标可继续优化 / <pass 带 feedback 下一轮 / 达上限或平台期 → 保留最优+ESCALATE
```

- 代码环默认：pass 7.0 / target 8.0 / ≤5 轮（五维：正确性30/效率15/可读性15/鲁棒性20/创新性20）
- 论文环默认：pass 6.5 / target 7.5 / ≤4 轮（五维：假设15/创造性25/结果30/表述20/格式10）
- 阈值可改：编辑 `state/decision_log.json` 的 `termination`。
- Git：每轮一个分支 `round{N}_{任务}_{slug}`，评分 ≥ pass 才 merge 回 main；评分挂 `git notes`（`git log --show-notes=score` 横向对比各轮）；每轮自动追加 `LogRecord/version-update.md`。
- **报告留存**：每轮 `round-score / round-decide / result-ingest` 自动把独立审阅 Agent 实验报告、决策报告、结果归档写入 `state/reports/`（index.json 索引，`report-list` 查询），供后续阅读、对比和改进；修复循环的多份同轮报告按时间戳独立保留。
- **全自动驱动**：`python shared/state-engine/orchestrator_runtime.py --plan-iteration N4 --dir . --git` 生成完整迭代序列（每轮 round-start → 执行 → round-score → round-decide），前置缺失时返回 blocked 与缺失清单；宿主按序执行即可无人值守跑到终止条件。
- **容错与降级**：子代理失败自动按指数退避重新调起（resilience.py）；高并发被限流时自动降级（并发减半→串行）并留痕；H 门禁默认"自动核查先行"——委托配对核查 Agent 核验（auto-check，生成核查报告到 state/reports/，门禁置 auto_passed）流程不挂起，用户回来后 h-confirm 追认。
- **节点自动审阅与返修**：节点交付默认走"独立审阅 → FAIL 返修（≤2 次）→ 复审"闭环（review-loop 生成序列）；审阅必须附 evidence（防走过场）；返修必须产生产物哈希变化（空返修打回，防 AI 偷懒）；达上限转 BLOCKED/ESCALATE（防死循环）。详见 mm-iteration-engine SKILL §5.1/§5.2。
- 初始化时 Agent 会**提醒你创建 GitHub 远端仓库**：`git remote add origin <url>` + 推送由你执行（Agent 不代做推送）。

## 6. state_utils.py 常用命令

```bash
python state/state_utils.py init --dir . --name CUMCM --problem A --git   # 初始化+预建 state+git 首次提交
python state/state_utils.py dump                                                # 查看全局状态
python state/state_utils.py node-start N4 --goal "Q1 求解器正确率 ≥95%"      # 节点开工
python state/state_utils.py claim coder --node N4                              # 子 Agent 租约（含 ttl 防重复派发）
python state/state_utils.py node-finish N4 --agent coder --artifact Code/main.py        # 节点完成+登记产物
python state/state_utils.py node-review N4 --agent mm-code-reviewer --result PASS \
    --skills "mm-iteration-engine,mm-algorithm-dev,code-review" --summary "五维 7.8"
python state/state_utils.py round-start N4 --goal "..." --branch round1_q1_solver --git
python state/state_utils.py round-score N4 --round 1 --total 7.8 \
    --dims '{"correctness":8.0,"efficiency":7.0,"readability":8.0,"robustness":7.5,"innovation":7.0}' \
    --judge mm-code-reviewer --git
python state/state_utils.py round-decide N4 --round 1 --feedback "向量化内层循环" --git
python state/state_utils.py case-add --title "SLSQP 求解 2024A 官方优秀方案" --source "CUMCM 2024 A 优秀论文" \
    --summary "..." --score 8.5 --source-type contest-papers --query "CUMCM 2024 A SLSQP"
python state/state_utils.py search-source add --id my-channel --type "代码" --name "我的仓库" --address "..." --tool "WebSearch" --query-template "<kw>" --apply-when "需要参考实现"
python state/state_utils.py dashboard-refresh                                  # 重建总状态工作栏（含 S 门禁 + 节点最近审阅）
python state/state_utils.py project-audit --dir . [--source 题目原文]          # 接手审计：题目比对/结构/节点首页/registry/状态-产物一致性/旧命名
python state/state_utils.py project-repair --dir . [--apply]                   # 按审计结果补建标准设施（不覆盖已有文件与状态）
python shared/state-engine/orchestrator_runtime.py --plan-iteration N4 --dir . --git   # 生成完整自动迭代序列（dry-run）
```

> init 幂等：已初始化项目再 init 会被拒绝（`--force` 才重建并清空）；脚本在 init 时复制进项目 `state/state_utils.py`（自包含）。

## 7. ZCode/Codex 插件适配（goal / loop）

| 插件 | 映射 |
|------|------|
| goal | 项目目标 ↔ `termination`（pass/target/max_rounds）；每轮目标 ↔ `rounds[n].goal` + 节点首页"本节点 goal"区；未达成 → 触发下一轮 |
| loop | 驱动 SEARCH→DECIDE 循环，退出条件读 `termination`，每轮落盘 `rounds[]` |
| TaskCreate/TaskUpdate | ↔ 节点首页刷新 + node-start/node-finish |
| subagent | ↔ 专用审阅 Agent（审阅必须独立子代理执行） |
| 无插件平台 | orchestrator 手动驱动等价循环，`meta.platform_mode` 如实记录（不谎报） |

分支名 / commit trailer / git notes 均可被插件与 `git log --grep "Round:"` 直接检索。

## 8. 与辅导课口径对齐

- **五大主线**：标准项目初始化（Phase 0 脚手架 + .gitignore + requirements + state 预建）、GitHub 协作（round 分支 + trailer + notes + 提醒建远端仓库）、AI Agent 工具（9 节点独立调用 + 审阅配对 + 注册表）、图表规范（output 唯一输出口 + ResultFigures 精选去冗余 + figure-list）、LaTeX 编译（ReportPaper/LaTeX + latex-guard 编译链）。
- **学生实操六步**：准备材料放 Data/raw → 触发 `/mathematical-modeling` → 托管运行（每阶段落盘+审阅）→ 取用成果（ReportPaper + SubmissionPackage）→ 精准介入（单独调用节点/round 分支回退）→ 学习路径（先跑通全链路再逐节点精修）。
- **P11 纵向比较四步**：round 分支 + 评分 notes 天然支持"多方法纵向对比"——`git log --show-notes=score` 即可横向对比各轮各方法得分。

## 9. 检索地址注册表（SEARCH 网络搜索源）

`state/search_sources.json`（init 预建，可 `search-source add` 扩充）登记迭代搜索的网络地址。SEARCH 步骤先读此表，**按实际需求选源**：

| 渠道 | 类型 | 调用方式 | 适用场景 |
|---|---|---|---|
| github-code | 开源项目/代码 | gh_grep + WebSearch | 参考实现、开源代码 |
| paper-academic | 论文/算法 | paper-mcp + WebSearch | 方法论、算法原理 |
| paperswithcode | 论文+代码对照 | WebSearch | 论文+官方实现成对证据 |
| contest-papers | 竞赛优秀论文 | WebSearch | 获奖论文参照、评分点对齐 |
| lib-docs | 库/框架文档 | context7 | 库 API/报错排查 |
| model-zoo | 预训练模型/数据 | WebSearch | 数据集/预训练模型 |
| zh-knowledge | 中文方法线索（非权威） | WebSearch | 仅作线索 |

**需求→渠道映射**：要代码→github-code/paperswithcode；要原理→paper-academic；要对标→contest-papers；要库用法→lib-docs；要数据/模型→model-zoo。**检索词模板**：`题型关键词 + 任务动词 + 数据形态`，中英文各一轮。**优先级铁律**：官方/论文/获奖论文/开源 > 社区帖；社区帖只作线索，落地前回源头验证。命中案例用 `case-add --source-type <渠道> --query <检索词>` 沉淀，保证"哪个地址+什么词"可追溯。
